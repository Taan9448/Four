# ASSET_PIPELINE — 명세 → 생성 → 자르기 → 검증 → 연결

그래픽은 OpenAI Codex가, 명세·코드·연결은 Claude Code가 맡는다. 두 AI가 같은 파일을 고치지 않도록 폴더 소유권을 CI가 강제한다.

## 1. 폴더 소유권

| 경로 | 주인 | 비고 |
|---|---|---|
| `assets/source/` | Codex | 원본 시트 `<id>.png` + 실제 프롬프트 `<id>.prompt.txt` |
| `assets/sprites/<id>/` | Codex(스크립트 결과) | `frame_XX.png`, `meta.json`, `_contact.png`, `_preview.gif` |
| `assets/placeholders/<id>/` | Claude(스크립트 결과) | 임시 시트 `_sheet.png` + 같은 형식의 결과 |
| `specs/assets/` | Claude | 에셋 명세. Codex는 읽기만 한다 |
| `assets/manifest.json` | 아무도 커밋 안 함 | `tools/build-manifest.mjs`가 dev·build·test 전에 생성 |
| 그 밖(src, data, tools, docs, 설정) | Claude | |

CI(`tools/check-ownership.mjs`): `art/*` 브랜치는 `assets/source/**`·`assets/sprites/**` 외를 바꾸면 실패. 그 밖의 브랜치는 이 두 폴더를 바꾸면 실패. `assets/manifest.json`은 누구도 커밋할 수 없다.

## 2. 시트 규격 — 128 그림 격자, 160 프레임 픽셀 아트

**그림 격자(draw)와 프레임(logical)을 나눈다.** 모델에게는 칸당 128×128 격자(블록 4px, 칸 512의 정수배)로 그리라고 하고, 게임 프레임은 그보다 큰 160×160이다. 모델이 칸을 꽉 채우거나 도끼를 치켜들어도 줄이지 않고 담는다.

**2026-10-07 64 → 128 변경(사용자 결정).** 모델은 64 격자를 요청해도 그보다 세밀하게(128 격자에 가깝게) 그린다. 64로 줄이면 얼굴·무늬가 뭉개지고 점이 지저분해졌다(엘리아·카일). 같은 원본을 128로 자르면 원본에 가깝게 살아나므로, 모든 전투 픽셀 아트를 128로 올렸다. 명세에서 `size`를 생략하면 large(128 → 160)이고, `size: small`(64 → 80)은 옛 규격으로만 남는다. 화면에서의 캐릭터 크기는 같다(프레임이 커진 만큼 화면 칸 안에서 촘촘해진다).

**기본 원칙: 에셋 하나 = 시트 이미지 한 장 = 생성 한 번.** 모든 프레임을 격자로 배치한 시트 한 장을 받아 `tools/slice-sheet.mjs`로 자른다.
이미지 모델은 **확대된 픽셀 아트**를 그린다. 모델은 요청한 블록 크기를 정확히 지키지 못하므로(PR #10: 요청 16px, 실제 약 13px, 이미지도 1254px), 도구는 크기를 가정하지 않는다. 자르기 도구는:
1. 시트를 **리사이즈하지 않고**(비율만 확인) 키 색 제거
2. 색이 바뀌는 위치들의 주기로 **실제 블록 크기와 격자 위치를 감지**(레일리 검정, 약수 주기는 배제)
3. 칸마다 블록 안쪽을 샘플링해 최빈색 → 마스터 팔레트(ART_STYLE.md, 32색)의 가장 가까운 색. 무채색에 가까운 색(숯빛 옷 같은 중간 회색)은 팔레트의 회색 계열(#0b0b10·#1d2433·#2b2b3a·#3d4459·#5d6478·#8a90a3·#c2c6d1·#f1efe6)에서만 고른다(살짝 따뜻한 회색이 갈색으로 붙는 것 방지)
4. 모델이 그린 원래 해상도를 **목표 프레임(160×160)에 그대로 담음**. 시트 전체에 같은 배율·같은 세로 위치를 쓴다: 캐릭터는 **시트의 행마다** 가장 낮은 줄(발)을 기준선 줄 144(160 × 0.9)에(모델이 행마다 기준선을 다르게 그리는 버릇 보정, 공중 동작이면 명세에 `row_align: false`), 가로는 칸 가운데를 프레임 가운데에 맞추고, 가장자리 1px은 늘 비운다. 여백 1px을 두고도 들어가지 않으면(인물이 칸을 꽉 채움) 시트 전체를 같은 비율로 축소(경고), 절반 이하면 정수배 확대(경고)
5. `frame_XX.png`(160×160)로 저장. meta.json에 감지한 블록 크기(`pixelScale`), `nativeSize`, `fit`, `gridPurity` 기록

| type | size | 캔버스 | 격자 | 칸 | 그림 격자(draw) → 프레임(logical) | 블록 | 배경(chroma) |
|---|---|---|---|---|---|---|---|
| `character-anim` | large(기본) | 1536×1024 | 3×2 | 512×512 | 128 → 160 | 4 | 마젠타 #FF00FF(보라·붉은 계열은 초록 #00FF00) |
| `character-ref` | large(기본) | 1024×1024 | 2×2 | 512×512 | 128 → 160 | 4 | 캐릭터의 키 색. 칸1 정면 3/4, 칸2 측면 |
| `fx` | large(기본) | 1536×1024 | 3×2 | 512×512 | 128 → 160 | 4 | 검정 #000000(자를 때 투명으로) |
| (옛 규격) | small | 위와 같음 | | | 64 → 80 | 8 | 2026-10-07 전 에셋. 다시 자를 때 large로 |
| `background` | — | 1536×1024 | 1 | — | 384×256(같음) | 4 | 없음(전투 배경, `bg_<장소>`) |
| `icon-sheet` | — | 1024×1024 | 4×4 | 256×256 | 64 → 64 | 4 | 마젠타. 칸마다 아이콘 하나(최대 16), 화면에서 24~32px로 줄여 씀(`icons_status`·`icons_intent`) |

최대 프레임: 6(3×2). 모든 캐릭터 칸이 512px로 같아 모델이 그리는 해상도가 시트마다 고르게 나온다. 블록 값은 "요청" 크기이며 실제 크기는 감지한다.

일러스트 명세는 `framing`(구도·잘라 쓰는 자리)과 `style`(화풍을 ART_STYLE 기본 대신)을 더 쓸 수 있다.
**화면 그림은 실제 그림이 들어온 것만 게임에 쓴다**(전투 배경·지도·시작 화면·아이콘). 그 전에는 CSS 바탕과 한자 배지가 대신하고, 임시 시트는 파이프라인 시험용이다.

자르기 도구는 출력 크기로 줄여 `frame_01.png`를 만든다. 검증은 비율·크기·meta 일치만 본다(격자·팔레트·여백 검사 없음).

**픽셀 갈래 공통 규칙**
- **프레임 번호는 모든 파일(명세, meta.json, 코드)에서 1부터.**
- 같은 캐릭터는 모든 칸에서 크기·의상·색이 같다. 사람형은 약 96px 키(칸 높이의 약 3/4), 발의 가장 아래 픽셀은 128줄 중 115번째 줄(baseline 0.9), 가로 가운데. 프레임에서는 160줄 중 144번째 줄. 아군은 오른쪽, 적은 왼쪽.
- 1px 외곽선 `#1d2433`, 색마다 2~3단계 명암, 스프라이트 하나에 16색 이하(이펙트 12색).
- 격자선·테두리·글자·숫자·워터마크·안티에일리어싱·흐림·그라데이션 금지. 칸 가장자리 5px 비움. 빈 칸은 순수 배경색.
- 크기가 다를 때: 비율이 같으면 규정 크기로 리사이즈해 자르고(경고), 비율이 다르면 실패.
- 크로마키 제거: 키 색과의 거리 < `chroma_tolerance`(기본 90)면 투명, 그 2.2배까지는 반투명 + 색 번짐 제거(블록 판정 전).
- 마젠타 키의 안쪽 픽셀: 픽셀 트랙도 마젠타 기운이 뚜렷한 픽셀(min(R,B)−G > 30)은 중성으로 돌린다(팔레트의 보라 #4b3a6b는 17이라 남는다. 늑대 불꽃 끝의 붉은 점 원인).
- 일러스트 + 마젠타 키: 키 색이 짜임·머리카락 틈으로 스며 안쪽 불투명 픽셀에 보라·분홍 기운이 남는다. 빨강·파랑이 모두 초록보다 높은 만큼을 빼서 중성으로 돌린다(빨강·피부는 그대로). 마젠타 키 인물에는 원래 마젠타 계열을 쓰지 않으므로 안전하다. 검증기는 마젠타 기운 픽셀이 0.05%를 넘으면 오류로 잡는다(옛 도구로 자른 그림; 임시 그림은 제외).
- 명세에서 `palette: free`로 팔레트 맞춤을 끌 수 있다(특수한 경우만).
- **게임 표시:** 정수배(기본 3배), 보간 없음(`image-rendering: pixelated`, `imageSmoothingEnabled = false`).

## 3. 표준 애니메이션 세트

| 이름 | 프레임 | fps | 반복 | 이벤트 프레임 | 높이 허용 편차 |
|---|---|---|---|---|---|
| idle | 4 | 6 | 반복 | — | 8% |
| attack | 6 | 12 | 1회 | hit: 4 | 20% |
| skill | 6 | 12 | 1회 | cast: 4 | 25% |
| hit | 3 | 12 | 1회 | — | 15% |
| death | 6 | 10 | 1회 | — | 검사 안 함 |
| fx | 최대 6 | 15 | 1회 | impact: 중간 | 검사 안 함 |

명세의 `bbox_tolerance`로 바꿀 수 있다(예: `haun_attack`은 칼을 머리 위로 드는 프레임 때문에 35%).

**캐릭터별 세트:** 하운·엘리아·카일·보른 = ref + 전체 세트(skill 포함) + 일러스트 설정화·초상화 / 왕일검 = 초상화(일러스트) / 일반 적 = ref + idle·attack·hit·death / 보스 = 적 세트 + skill.

## 4. 일관성 전략과 대체 단계

- 캐릭터마다 기준 시트(`<char>_ref`)를 먼저 만든다. 칸1 3/4 정면 전신, 칸2 측면 전신(애니메이션과 같은 방향).
- 애니메이션 시트는 기준 시트를 참조 이미지로 넣어 생성한다. 명세의 `depends_on`에 기준 시트를 적고, 선행 에셋이 머지되기 전에는 처리하지 않는다(이슈에 `blocked` 라벨).
- 2회 재시도해도 프레임 간 모습이 어긋나면 내려간다. 사용한 단계는 `meta.json`의 `fallbackLevel`.
- **대체 단계는 프레임 불일치 전용이다.** 기준 시트에는 쓰지 않고(항상 전신 2칸), 격자 문제(감지 실패·일치도 미달·흐림)도 대체 단계로 풀지 않는다. 격자 문제는 2회 재시도 후 멈추고 Claude에게 넘긴다(도구·규격 쪽 문제일 가능성이 높다). 격자 감지 실패는 이제 경고라 재시도하지 않는다.

| 단계 | 시트 | 자르기 | 게임 재생 |
|---|---|---|---|
| 1(기본) | 전체 프레임 | `assets:slice -- <id>` | 그대로 |
| 2 | 키 포즈 3장(준비·타격·회복) | `assets:slice -- <id> --fallback 2` | SpritePlayer가 `virtualFrames` 길이로 보간 |
| 3 | 파츠(머리·몸통·팔·무기) | `assets:slice -- <id> --fallback 3` | 이후 관절 애니메이션(1차에는 첫 파츠만 표시) |

## 5. 명세(`specs/assets/<id>.yaml`)

템플릿은 `specs/assets/_template.yaml`. 명세에는 `status` 필드가 없다 — 상태는 파일로 계산한다(`npm run assets:status`).
- `requested`: 명세만 있음
- `delivered`: `assets/sprites/<id>/meta.json`이 있음
- `integrated`: 사람이 게임에서 확인한 뒤 이슈에 라벨

**meta.json**(스크립트 생성): `id`, `type`, `frameW`, `frameH`(논리 해상도), `pixelScale`, `gridPurity`, `frames`, `fps`, `loop`, `anchor: [0.5, baseline]`, `events`, `blend`(normal | lighter), `facing`, `fallbackLevel`, `virtualFrames`, `sourceHash`, `placeholder`, `resizedFrom`.

## 6. 검증(`npm run assets:validate`, CI에서도 실행)

- 명세 모양(cell×grid = canvas, frames ≤ 칸 수, 이벤트·frame_notes 범위, depends_on 존재, reference)
- 캔버스 비율·크기
- 1~frames 칸에 그림이 있는지, 그 뒤 칸이 비었는지
- meta.json과 명세 일치, 프레임 파일 수
- **블록 격자 감지**: 고른 격자를 못 찾으면 명세 배율(`pixel_scale`)로 128 격자에 맞춰 자르고 **경고**(2026-10-07 변경). 이미지 모델은 블록 크기를 조금씩 다르게 그리기 쉬워 감지가 실패해도 결과는 쓸 만하다. 이때 일치도는 픽셀 아트와 일러스트를 가르지 못하므로(둘 다 35~50%) 막지 않고, Claude가 콘택트 시트를 눈으로 보고 승인한다
- **픽셀 격자 일치도**(감지한 블록 안이 한 색인 정도, 격자를 감지했을 때만): 65% 미만 경고, 50% 미만 실패. 대체 단계 3(파츠)에서도 검사
- 모델 해상도가 목표보다 커서 줄였거나, 절반 이하라 확대했으면 경고
- 프레임이 게임 프레임 크기(160×160 등)인지, 모든 색이 마스터 팔레트 안인지(실패), 색 수가 권장치 이하인지(경고)
- 키 색 잔여 픽셀(불투명 픽셀 중 채도 높은 키 색 비율 > 0.5%면 실패)
- 그림이 칸 경계에 닿았는지(실패), 가장자리 5px 여백 침범(경고)
- 프레임 간 바운딩 박스 높이 편차(애니메이션별 허용치, 1px 흔들림 허용, 대체 단계 1에서만)
- **옛 규격으로 자른 프레임**(명세가 바뀐 뒤 아직 다시 자르지 않음, 예: 2026-10-07 64 → 128 전환): 그 art 브랜치가 맡은 에셋(`art/<이슈>-<id>`의 id)이면 실패, 다른 에셋·다른 브랜치는 경고(2026-10-08: 아직 다시 그리지 않은 하운 때문에 모든 아트 PR의 CI가 막혀 범위를 좁혔다). `assets:status`에 `reslice`로 표시되고, Codex가 `assets:slice -- <id>`만 다시 실행하면 된다(재생성 불필요)
- 통과하면 `_contact.png`(번호·이벤트 표시, 정수배 확대)와 `_preview.gif`를 결과 폴더에 남긴다.

## 7. manifest와 자동 교체

`tools/build-manifest.mjs`가 `predev`·`prebuild`·`test`·`typecheck` 전에 모든 `meta.json`을 모아 `assets/manifest.json`을 만든다.
게임은 에셋 id를 **`assets/sprites/<id>` → `assets/placeholders/<id>`** 순서로 찾는다. 아트 PR이 머지되면 코드 수정 없이 임시 시트가 실제 그림으로 바뀐다.

## 8. GitHub 협업 흐름

- **라벨:** `asset-request`, `codex`, `claude`, `needs-fix`, `integrated`, `blocked`
- **브랜치:** `main` 보호(PR + CI 통과 후 스쿼시 머지). 아트 `art/<이슈번호>-<id>`, 코드 `feat/…`·`fix/…`(또는 세션 지정 브랜치)
- **커밋 접두어:** `art(<id>):`, `feat(<영역>):`, `fix(<영역>):`, `docs:`, `ci:`

1. **Claude — 요청.** `specs/assets/<id>.yaml` 작성 → `npm run assets:placeholder -- <id>`(게임이 먼저 돌아가게) → `npm run assets:prompt -- <id>`로 완성 프롬프트 → 에셋 요청 이슈(라벨 `asset-request`, `codex`, 선행 에셋 대기면 `blocked`). 본문: 명세 경로, 한 줄 요약, 선행 에셋, 완성 프롬프트 전문, 참조 이미지 경로.
2. **사람 — 전달.** Codex 앱·CLI에서 "이슈 #N AGENTS.md 절차대로 처리해". 클라우드는 이슈 댓글 "@codex AGENTS.md 절차대로 이 이슈 처리해".
3. **Codex — 제작.** AGENTS.md 순서: 생성 → `assets:slice` → `assets:validate` → 콘택트 시트 확인 → 아트 PR(`codex`, `Closes #N`).
4. **CI — 자동 검증**(`validate.yml`): 소유권 검사, 타입 검사·데이터 검사·테스트, 에셋 검증, 빌드.
5. **Claude — 검토.** `_contact.png`·`_preview.gif` 확인. 문제가 있으면 "몇 번째 프레임이 무엇이 틀렸는지" PR 댓글 + `needs-fix`. 통과면 "아트 승인" 댓글.
6. **Claude — 머지.** "아트 승인" + CI 통과면 스쿼시 머지(초안 해제·`needs-fix` 제거 포함)하고 사람에게 알린다.
7. **Claude — 확인.** 게임에서 자동 교체 확인 → 이슈에 `integrated`. 이 에셋을 기다리던 이슈의 `blocked`를 푼다. 이벤트 프레임 타이밍 조정 같은 코드 변경이 필요할 때만 `feat/<id>-integrate`.

## 9. 미리보기

`npm run dev` 후 `http://localhost:5173/tools/preview.html?id=<id>` — SpritePlayer로 재생하고 이벤트 발생을 표시한다.
`http://localhost:5173/?sandbox` — 지도 없이 바로 전투(융합 카드·왕일검 지원 포함)로 연출을 확인한다.
